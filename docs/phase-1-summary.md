# 一期总结

## 项目定位

- 项目名称：`Universal Video Downloader`
- 一期目标：先完成“解析链接 -> 选择格式 -> 创建任务 -> 查看进度 -> 领取文件”的核心闭环。
- 合规边界：仅处理合法公开内容，不支持 DRM、付费墙、登录态内容、Cookie 导入、风控规避和批量抓取。

## 本期已完成

### 前端

- 使用 `Vue 3 + Vite + Tailwind CSS` 完成首页和任务页。
- 首页包含：
  - 强操作入口的视频链接输入区
  - 解析结果预览
  - 格式选择
  - 核心卖点卡片
  - 三步流程说明
  - 合规说明
- 任务页包含：
  - 任务状态与进度轮询
  - 稳定下载入口
  - 极速直连入口
  - 代理下载入口
  - 24 小时临时领取链接

### 后端

- 使用 `FastAPI` 提供下载相关接口。
- 使用 `yt-dlp` 作为统一解析和下载内核。
- 使用 `ffmpeg` 处理需要音视频合并的格式。
- 使用本地文件系统保存任务和产物，不接数据库。
- 实现了：
  - 视频解析
  - 任务创建
  - 任务状态查询
  - 稳定下载
  - 极速下载
  - 过期任务清理

### 运行与交付策略

- 下载模式采用“自动最优策略”：
  - 默认：稳定下载
  - 条件满足时：补充极速下载
- 文件保留时长：`24 小时`
- 交付范围：当前设备下载 + 临时链接跨端领取

## 本期明确未做

- 用户体系
- 会员 / 支付
- 批量下载
- 字幕提取 / 字幕翻译
- 视频总结
- 历史记录数据库化
- 后台管理端

## 关键技术决策

- 前端技术栈固定为 `Vue 3 + Vite + Tailwind CSS`
- 后端技术栈固定为 `FastAPI + yt-dlp + ffmpeg`
- 二进制不依赖系统全局环境，统一放在 `runtime/bin/`
- 任务状态不入库，落盘到 `runtime/tasks/<taskId>/task.json`
- 下载执行使用后台线程池，不阻塞接口请求

## 当前验证结果

### 已完成验证

- 前端构建通过：`npm.cmd run build`
- 前端单测通过：`npm.cmd run test:run`
- 后端单测通过：`pytest` 共 3 项

### 验证时的环境说明

- 当前机器的 `pip` 直接联网安装依赖存在源/代理问题。
- 为完成后端验证，使用了本机已有的 Anaconda Python + 临时本地 FastAPI 验证路径完成测试。
- 这不影响项目代码结构，但二期继续开发前，建议先把标准 Python 依赖安装链路修通。

## 当前已知限制

- 一期没有真实下载任务列表页，只有首页和单任务详情页。
- `yt-dlp` 与 `ffmpeg` 需要先手动或脚本下载到 `runtime/bin/`。
- 后端 `FastAPI` 关闭事件目前使用 `on_event("shutdown")`，存在弃用警告，后续建议改为 lifespan。
