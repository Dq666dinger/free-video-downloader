# 二期接手说明

## 当前接手前先确认的事实

### 已锁定的产品决策

- 前端技术栈继续使用 `Vue 3 + Vite + Tailwind CSS`
- 后端技术栈继续使用 `FastAPI + yt-dlp + ffmpeg`
- 当前项目默认 Windows 开发环境优先
- 二进制采用项目内托管，不改为系统全局依赖
- 下载模式继续保留：
  - 稳定下载
  - 条件式极速下载
  - 24 小时临时链接

### 一期未做，不要误判为遗漏 bug

- 批量下载不是漏掉，是明确未做
- 用户、会员、支付不是漏掉，是明确未做
- 字幕、总结不是漏掉，是明确未做
- 数据库不是漏掉，是明确未接

## 建议二期优先顺序

### P1：把当前一期基础打稳

1. 修通标准 Python 依赖安装链路
2. 改 FastAPI `on_event` 为 lifespan
3. 增加真实任务列表页
4. 增加任务失败后的“重试”能力
5. 补一轮真实下载 smoke 测试脚本

### P2：增强下载产品能力

1. 批量任务
2. 任务管理页
3. 历史记录
4. 任务过期提示和清理页

### P3：扩展增值能力

1. 字幕下载 / 自动字幕提取
2. 字幕翻译
3. 视频总结
4. 用户系统
5. 会员 / 付费能力

## 已知技术风险

### 环境风险

- 当前机器的标准 `pip` 安装链路不稳定。
- 接手开发前，最好先确认：
  - Python 版本
  - pip 源配置
  - 代理配置
  - `yt-dlp` / `ffmpeg` 是否已下载

### 代码风险

- 当前任务执行依赖线程池，后续如果引入批量任务，需要重新审视并发控制。
- 当前格式筛选逻辑是一期简化版，后续可能需要更细的分辨率/音轨/字幕策略。
- 当前任务 JSON 为单文件持久化，任务量增大后需要考虑索引或数据库。

### 产品风险

- 极速下载并不是所有平台都能命中，前端文案必须继续保持“条件可用”表达。
- 合规边界必须继续保留，后续不能因为加功能而默认支持登录态内容。

## 二期开发前 checklist

- 阅读 `docs/phase-1-summary.md`
- 阅读 `docs/phase-1-architecture.md`
- 阅读 `docs/phase-1-api-contract.md`
- 先本地跑通前端构建和前端测试
- 确认后端依赖环境可安装
- 确认 `runtime/bin/` 中的下载内核已就绪
- 用一个合法公开视频链接手工走完一期主流程

## 建议保持的开发原则

- 优先复用 `yt-dlp`，不要手写平台解析器
- 优先补全核心闭环，不要同时扩太多高级功能
- 关键产品策略先确认再做
- 新功能默认写清楚“是否在合规边界内”
- 每做完一个阶段，都把结果继续沉淀进 `docs/`
